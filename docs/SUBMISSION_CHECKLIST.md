# Submission checklist

Use this checklist when you are about to submit the manuscript.

## Repository

- Confirm that the GitHub repository is public.
- Confirm that the main manuscript-ready commit is the intended one.
- Confirm that no sensitive or unintended files remain in the repository.
- Confirm that the README still matches the manuscript title and analysis pipeline.

## Release archiving

- Create a tagged GitHub release for the exact submission version.
- Archive that release in Zenodo or Dryad.
- Record the DOI returned by the archive service.
- Update `docs/MANUSCRIPT_TEXT.md` and the manuscript/submission form with the DOI.

## Manuscript text

- Paste the Data Availability statement from `docs/MANUSCRIPT_TEXT.md`.
- Paste the Code Availability statement if the journal or submission system asks for it separately.
- Add the archived repository DOI to the reference list if requested.

## Licensing

- Confirm that MIT for code and CC BY 4.0 for data/media is acceptable to all coauthors and institutions.
- If a different licence is preferred, update `LICENSE`, `LICENSE-CODE`, `LICENSE-DATA`, `README.md`, and `CITATION.cff` together.

## Royal Society policy checks

- Confirm that all data and code supporting the article are publicly available.
- Confirm that the Data Availability statement does not say "available on request".
- Confirm that the final archived landing page displays the open licence clearly.
